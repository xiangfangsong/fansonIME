## 交付范围

- 仅五笔默认开启本地学习；关闭恢复原固定查询和顺序，停止学习且保留记录。
- 14 天半衰期、16 分上限、≤0.25 失效；自定义短语、精确、补全分层，层内稳定排序；简繁输出和输入码分别维护。
- 内存哈希及有序索引，最多两万条；键盘真实隐藏后后台批量保存变化；无定时任务、次数阈值、周期重试或销毁兜底。允许丢失未保存记录。
- 平台接受的五笔候选才计分；原始编码、标点、空白、其他语言、隐私及内部 emoji 搜索不计分。隐私和搜索也不应用个人五笔顺序。
- 三个独立清空按钮；清空词频不改开关，清短语仅去失效学习且保留相同内置来源，设置和剪贴板保留；防止旧保存/反馈复活。
- version 1→2 个人库增量迁移，保留旧数据，启用 WAL；保持备份排除，不更改应用 ID 或签名配置。

### 开发中发现并修正

1. 初次 JVM 用例在同分记录中假定固定淘汰身份，实际同分采用稳定来源键决胜；修改合成数据明确区分频率，重跑通过。
2. 新增 UI 测试助手把候选栏的编码 TextView 当成首个 Button，导致仪器进程崩溃；改为按实际控件类型找候选。生产输入逻辑未因此改变，随后完整 124 项通过。
3. 首次 Lint 提示共享组件持 Context 的静态引用风险；构造参数和持有字段收敛为 Application，避免服务/Activity 引用并消除警告。
4. 初轮近似堆值包含临时分配/GC 干扰。索引优先级改为每条记录更新时计算一次，比较器不再反复算对数和装箱；测量也改为等待显式 GC 后采样。后续数值不能全部归因于单一优化。
5. 复查发现满表高分记录可能使新记录自我淘汰，导致学不到新习惯；改为先淘汰旧表最低项再接纳新项，新增 JVM 回归。清空大量短语改为一次来源集合扫描，避免短语数乘词频数的重复遍历。

6. 隐藏后的整批整理曾连续持锁约 50 ms，改为每 128 行释放锁并主动让出线程；成功确认同样分批。新增并发过期/新选择检查。
7. 写入中的插入单独追踪，成功后才确认磁盘集合，事务回滚清理无效删除标记。新增连续 200 轮失败的有界 dirty 回归，避免磁盘失败时内存反而无限增长；显式清词频的数据库失败会保留模型供重试。

## 性能实测

这里只报告本次 API31 x86_64 软件 GPU 模拟器的 Debug 合成数据，**不是手机、完整按键到屏幕或电量结果**。每个热态测量先预热 50 次，再采样 300 次；时间使用纳秒单调计时。近似堆增量用 Runtime 已用堆差，受 GC/运行时影响；不是严格 retained-heap 分析，也不是两万条最长短语的内存上限。

最终同次运行报告已归档为 [原始合成性能 JSON](frequency-performance-0.4.0.json)。两万条小型合成记录的近似堆增量为 **4902624 bytes（约 4.68 MiB）**。

| 测量项 | P50 / ms | P95 / ms | P99 / ms |
| --- | ---: | ---: | ---: |
| 200 候选，无学习记录 | 0.0009 | 0.0010 | 0.0010 |
| 200 候选，20,000 条同输入码记录 | 0.1167 | 0.2379 | 0.3582 |
| 同输入码 20,000 条中取 64 来源 | 0.0189 | 0.0518 | 0.0672 |
| 容量上限时更新已有记录 | 0.0043 | 0.0194 | 0.0246 |
| 20,000 条分散在 625 个输入码，取当前码来源 | 0.0110 | 0.0323 | 0.0599 |
| 固定仓库 a 查询 | 1.0695 | 1.5640 | 1.9551 |
| 学习引擎 a 查询，核对 64 个无效来源 | 1.3641 | 1.7757 | 2.0832 |

同次单次后台工作测量：隐藏整理到 18,000 条并准备快照 **19.06 ms**；初次 18,000 行事务 **181.77 ms**；一行变化事务 **0.89 ms**；18,000 行整批过期清理并准备删除快照 **47.24 ms**。整理和确认每 128 行释放模型锁；这里的总耗时不等于连续持锁时间，未独立测量每次最长锁等待。

学习查询与固定查询的 P95 差约 0.212 ms，但测量路径不同（学习项包含引擎快照及无效来源核对），不能当作严格隔离的公式 CPU 开销。正常排序开销较小；后台写入仍有磁盘、内存复制和锁竞争成本，WAL 不消除所有延迟。没有测量正式电量，不把这些数值解释为零耗电或真机端到端流畅度达标。
