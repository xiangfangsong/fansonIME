# 待改进事项与验证缺口

基于 2026-11-09 的 0.3.0 源码检查整理。这里区分实现限制与可优化结构，不表示已发生用户故障，也不表示本次已经修复。优先级为后续工作建议：先处理提交与隐私语义，再调整维护结构和性能；具体范围由后续任务确定。

## 输入正确性与隐私边界

| 编号 | 源码事实与影响 | 后续变更前需要明确/验证 |
| --- | --- | --- |
| G01 | 普通输入先推进引擎状态，再应用宿主编辑；`commitText()` 的失败通常没有传播回引擎。连接为空或宿主拒绝提交时，没有完整回滚/重放协议。emoji 次数已检查提交成功 | 明确部分成功、连接丢失、会话结束后的语义；用可控失败的编辑器验证不重复提交、不写入下一输入框 |
| G02 | `privateField` 包含 NO_PERSONALIZED_LEARNING；但英文补全关闭、候选隐藏、字根和 emoji 入口限制主要依据 `password`。非密码隐私字段仍可使用离线补全/emoji，但不更新 emoji 次数或自动记录剪贴板 | 与产品要求核对“禁止持久化”和“禁止展示建议”的区别，再决定是否收紧；补专用 EditorInfo/仪器测试，不先声称现有策略完全覆盖设计稿 |
| G03 | `onUpdateSelection()` 仅清理英文/韩语预编辑；五笔未在光标变更时清码。同会话异步任务依赖 FIFO，没有单独查询版本或连接快照 | 明确五笔移动光标的期望，以及排队输入遇到语言/面板/输入框切换的语义；新增快打和切换压力用例；不能简单丢弃含正文提交的旧结果 |
| G04 | 剪贴板监听跟随服务生命周期；`onFinishInput()` 清除隐私标志。隐私编辑结束后、默认 IME 服务仍运行时的复制会按普通后台复制处理 | 明确会话结束后的隐私保护时限和产品预期；用合成数据验证锁屏、面板外、隐藏键盘、隐私结束等边界 |

## 资源与数据可靠性

| 编号 | 当前实现 | 后续验收方向 |
| --- | --- | --- |
| G05 | 任一离线资源初始化异常都会导致整个输入链路未 ready；统一提示，没有重试或按语言降级；个人库创建还在该 catch 外 | 注入缺失/损坏资源、复制失败与库打开失败；明确可用模式、重试边界和非敏感错误诊断 |
| G06 | 已存在的哈希命名字典副本不再校验；未清旧副本；固定 `.tmp` 用于准备；当前假设单个 IME 初始化流程 | 数据升级/损坏恢复、异常中断及并发准备策略；清理只能作用于已确认不再使用的字典副本 |
| G07 | `LocalStore` 只有建表和 version 1 删除旧收藏的迁移；Activity/服务不同实例，方法同步不是跨实例锁 | 下次改表时先补迁移协议、旧库 fixture、事务及升级后数据保留验证；禁止以清库代替正常迁移 |
| G08 | `PhraseEncoder` 与 `stem` 字段存在，但无完整码查询和自动生成短语编码的实际界面链路 | 若启用自动取码，先定义一字多码、简码与完整码区别、缺字处理和用户确认；现阶段保持手动填写的产品描述 |

## 可维护性与性能

| 编号 | 当前实现 | 后续验收方向 |
| --- | --- | --- |
| G09 | 服务同时负责输入编排、状态、面板构建、系统交互；`panel` 用字符串，光标面板直接替换 body；`WubiRepository` 与 `LocalStore` 同文件 | 先按职责提取并保持提交顺序和线程归属，建立清晰输入目标/面板状态；每次提取以原行为回归验证，不同时大改引擎规则 |
| G10 | 普通候选刷新创建全部候选按钮再隐藏放不下的项；多处整段重建 View；emoji 字形过滤、英文前缀范围排序、部分 SQLite 写入在主线程；删除每次扫描 emoji 后缀 | 先测量冷启动、长词/大量候选、快打、低性能设备及连删；优化时核对顺序、字形、次数与字符簇完整性。设计稿中的 P95 30ms/首显 500ms 仍是未实测目标 |
| G11 | `verify_assets.py` 检查源 Manifest 与静态排除项；JVM 测试多用假词库；仪器测试集中在一个自定义 runner | 补编辑失败、资源失败、旧库迁移、非密码隐私标志、销毁与跨会话压力检查；最终 APK 权限/签名以及不同宿主、横屏和真机仍需独立验证 |

## 文档偏差的处理

`DESIGN.md` 的历史修订含早期设想，例如可回收列表、数据库候选分页、独立查询序号、单独隐私包和自动短语取码；这些不能当作当前架构。现行技术文档已按源码区分。产品原稿与版本验证记录保留历史语境，当前规则变更时同步技术章节。

关闭某项时写明对应变更、实际验证和仍存在的边界，再更新架构/输入/数据等正文；不要只删掉该行，让实现决策再次失去记录。
