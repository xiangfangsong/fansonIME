# 五笔本地词频维护说明（0.4.0）

实现状态：代码已实现，电脑端与真机验收状态分别见 [0.4.0 验证记录](../validation/VALIDATION-0.4.0.md)。用户已在本版真机确认功能生效并授权 Git 提交，算法长期体验仍待持续观察，未授权推送；不将该反馈写成长期效果或耗电验证通过。需求取舍和实施前方案见 [设计方案](proposals/2026-11-10-wubi-frequency.md)。

## 用户可见规则

- “输入习惯 → 五笔按本地词频排序”默认开启，包括旧安装缺少该设置时。未知设置值回退开启。关闭停止学习、恢复旧查询顺序，已有数据保留；重新开启继续使用。
- 仅五笔。自定义短语、内置精确候选、前缀补全保持三个优先层级，各层按当前有效分数降序，同分稳定保持基础顺序。
- 不改变当前已经显示的候选快照；计分只影响后续重新查询。下一次输入、退格或切换简繁/读音等引发重新查询时可见变化。
- 点击、空格、四码唯一、第五码、回车首选，以及标点/切面板前确认的五笔候选，平台接受一次加 1。主动选择和自动提交权重相同；暂不做用户纠错推断和删除已上屏文字后的扣分。
- 原始编码、空白、标点、英文/韩语、剪贴板粘贴不计分。密码与 NO_PERSONALIZED_LEARNING 字段、emoji 内部搜索既不使用个人排序也不学习。后者只改变五笔学习边界，不扩大为本次范围外的英文建议策略修改。

## 算法：频率与近期性

定义 `H=14天=1,209,600,000ms`、`MAX_SCORE=16`、`EXPIRED_SCORE=0.25`：

```
age = max(0, now - updatedAt)
raw = score * 2 ^ (-age / H)
effective = raw > 0.25 ? raw : 0
成功提交：newScore = min(16, effective + 1)，updatedAt = now
```

存储的是 Double 衰减分数，不是终身使用次数。查询不更新时间戳；再次选择先衰减后加分，不能把全部历史重新变成“刚刚发生”。没有周期衰减任务：仅查询当前候选、反馈选词和隐藏整理时计算。

例：满分词此后未用，14/28/42/56/70 天分别剩 8/4/2/1/0.5 分；84 天到 0.25，失去加权并最终移除学习记录。三个近期选择可以超过六周前的满分记录。同半衰期下所有静置分数等比缩小，彼此排名本来不会自动交换；门槛使这些记录最终与未学习候选一起恢复基础顺序。

这些参数为首版经验选择，不是用户研究得出的最优值；五笔肌肉记忆可能不适合动态首选，开关提供固定排序。分数上限会让大量高频词同分，稳定基础顺序用于兜底；不额外用“最近一次”打破同分，以减少候选抖动。后续要改参数，应同时更新算法测试、合成场景、本文和产品说明；旧记录已压缩，不能精确按新参数重算过去的全部事件，应写明迁移近似与兼容处理，不能直接清空个人库。

时间来自墙钟，不读取输入内容上下文。加载时将未来更新时间夹到当前时间并标记待保存；运行时负间隔当作 0，避免时间回拨产生额外权重。人为大幅改时仍会影响遗忘进度，这是已知限制。

## 身份、简繁、来源验证与截断

主键 `(inputCode,sourceCode,sourceText,text)` 分别表示本次实际输入编码、来源完整/简码、转换前文字及最终输出文字。`custom` 是当前来源属性，不进入键：添加与内置同名的自定义短语可继续使用原学习，删除自定义项后如仍有同码同文内置项也可保留。

例如以 `a` 选中某个 `abcd` 补全，只影响 `a` 的这项候选；输入 `ab`、`abcd` 分别学习。转换 `发→發/髮` 时仍保留 `sourceText=发`，最终文字各有分数。简繁共用后完全相同的输出文字共用键，未凭空按模式复制记录。

`Candidate.custom/sourceText` 从查询开始附带，转换用 `copy(text=...)` 保留来源。基础查询仍按文字去重，先出现的自定义项优先；转换后的去重规则仍为 `(text,code,exact)`。频率在转换后排序，读音最后添加，不进入提交或学习键。

为避免旧查询上限隐藏已学常用项，每个输入编码最多补回 64 个未过期的内置来源：

1. 从当前输入码的有序索引按权重取来源；不同繁体变体指向同一来源时先去重。
2. 先执行旧查询；当前已有的文字不再补查。
3. 对缺失来源以绑定参数批量查询 `(code,text)`，最多 128 个参数、64 个 OR 条件；确认来源存在、源编码以当前码开头且仍在 a～y 的四码范围。
4. 以数据库当前返回内容构造候选，原词精确与补全分组；重新简繁转换并按当前分数排序。历史输出文字不能直接生成候选。

自定义短语仅精确匹配，原查询已完整返回，不新增前缀短语补全。64 是增补来源上限；基础精确查询至多 200 项和前缀补足至 40 项的规则保留，未实现无界全词典动态排序。关闭学习、隐私和搜索不补回，严格恢复旧查询。

## 内存与容量

模型进程内共享，`@Synchronized` 短临界区保护所有状态；引擎规则仍在原五笔 worker。最多 20,000 个当前记录：

- `HashMap<FrequencyKey,FrequencyRecord>`：单项计分查找。
- 每输入码 `TreeSet`：当前码常用来源提取；只访问相关码，不全表扫描。
- 全局 `TreeSet`：容量淘汰、隐藏时去除过期项。
- 有界 dirty 集合及已落盘/写入中键集合：批保存与删除追踪。

索引比较 `log2(score)+updatedAt/H`，它与相同当前时刻的指数分数顺序等价，因此正常时间前进不必每天重建索引。排序时有效分数只计算一次，不在比较器里反复算衰减。候选 N 个时排序 O(N log N)，单条更新及容量替换 O(log 20000)，来源取至多 64 个；极多自定义短语本来无查询上限，其界面构建成本仍是已知边界。

输入期间达到上限后，先从旧表逐条替换最低优先级记录再接纳新记录，防止满表高分时新词反复自我淘汰、永远无法累积分数；内存始终不超过上限；触及过容量的模型在下次隐藏整理到 18,000 条，避免不断在上限附近积累旧记录。分数过期只取消学习，不删词库和手动短语。

从未落盘且已被淘汰的记录直接丢弃 dirty，不为它永久留下删除墓碑。快照单独标记为“写入中”，成功确认后才归入已落盘集合，避免写入中淘汰漏删，也避免失败重试把从未保存的键永久当成磁盘记录。事务回滚后调用 failed()，清掉仅因本次在途插入产生的无效删除标记，其他 dirty 保留；反复写入失败同样有界。因此临时辅助集合可能超过当前两万记录，但受已保存集合与单个写入快照约束，不随无限输入增长。内存数值见本次合成实测，不能将条数乘单个数值字段大小当作真实 Kotlin 堆占用。

## 成功反馈、线程和会话

`EngineResult.selections` 使用 `WubiSelection(commitIndex,inputCode,candidate)` 与字符串提交逐项对应。第五码先记录旧码来源再 reset，不能读取操作后的新 `code` 计分；标点只给候选那一项附元数据，原始回车编码没有元数据。此扩展不改英文/韩语的 commits/composing 语义。

服务在入队时捕获 `FrequencyPermit(allowed,epoch)`。`allowed` 同时要求五笔、设置开启、非隐私、非搜索。原 session 在操作前和发布前继续验证。主线程逐项 `commitText()` 后把真实返回值送入 `accept()`，它再次核对提交索引和文字一致，只有被接受、资格有效且代数相同才更新内存；不读取或记录周边正文。

`enqueue()` 和独立 `enter()` 都反馈；`deleteKey()` 重新查询时也应用当前资格。成功计分不直接刷新正在展示的候选。后台可能已算好后续按键快照，所以快速连打时该计分影响下一次尚未执行的查询，不能强行丢弃中间含正文结果来追求立即重排。

平台返回成功不等于宿主最终落字；本次不补足编辑器拒绝后的引擎回滚。非敏感运行错误不打印编码、词条、SQL 参数或正文。

## 只在隐藏时保存

只有真实 `onWindowHidden()` 安排日常词频保存：包括自定义收起键盘、系统隐藏等。切面板或仅切输入会话不是保存触发条件；普通销毁不额外兜底，不设置定时器、闹钟、次数阈值、WorkManager 或周期重试。进程退出时未保存数据可丢失，符合用户明确取舍。

`WubiFrequencyStore` 只持 applicationContext 和自己的 LocalStore，跨服务重建共享同一模型；不随 service.close 关闭，不保存 Activity/View。独立 `wubi-frequency-disk` 单线程、后台优先级负责磁盘，与五笔查询队列分开。隐藏请求用 AtomicBoolean 合并，至多一个执行中及一个待执行请求；无变化时不开始写事务。

保存流程：后台按每批最多 128 条整理并释放模型锁 → 模型锁内取不可变变化快照及每项 revision/epoch → 释放锁 → SQLite 事务提交 → 每批最多 128 条加锁确认。背景分批之间主动让出线程，不用延时或定时调度；避免快速重新展开时等待整批过期扫描。快照仍是两万条规模的有界内存复制，不承诺零锁等待。若写入期间继续学习，同键新 revision 保留 dirty；若失败不确认已落盘集合，调用 failed() 去除在途的无效删除标记，保留其余待保存状态等下一次隐藏，没有定时重试。

清空、删除短语等显式用户操作是立即持久化的例外，都排到同一 I/O 队列。不能另起无序线程写同一词频表。清空先提升内存 epoch 拒绝旧反馈，再清数据库，成功后清模型；数据库失败时保留模型供重试，不把未清掉的旧库行误当成不存在。旧快照的写入与清空在同一队列串行，清空前的候选反馈携旧 epoch 被拒绝，从两个方向防止复活。

## SQLite 迁移与清除边界

个人库仍为 `noBackupFilesDir/personal.db`。version 1 → 2 仅事务新增表并提升版本，设置/短语/emoji/剪贴板保留；首次安装仍兼容原 version 0 收藏表处理。schema 操作由进程公共锁保护，不将 LocalStore 的实例锁误认为跨实例锁。

```sql
CREATE TABLE wubi_frequency(
  input_code TEXT NOT NULL,
  source_code TEXT NOT NULL,
  source_text TEXT NOT NULL,
  text TEXT NOT NULL,
  score REAL NOT NULL,
  updated_at INTEGER NOT NULL,
  custom INTEGER NOT NULL,
  PRIMARY KEY(input_code,source_code,source_text,text)
);
```

启动读取至多 20,000 条，过滤非法码、空/超长文字、非有限/非正分数和过期记录；修正超上限分数和未来时间。非法行成为待删记录，下次隐藏保存。读入排序按更新时间，不宣称可从任意外部篡改的无界库恢复全部最优记录。

各 LocalStore 连接启用 WAL，避免隐藏写入事务使其他连接的读操作等待整批保存。SQLite 仍只有一个写者，已有其他个人数据写入可能竞争；WAL 不保证零延迟，也不是加密。其旁文件仍位于同一无备份目录，`secure_delete` 不构成对全部物理存储副本的安全擦除承诺。

| 用户操作 | 删除内容 | 保留内容 |
| --- | --- | --- |
| 清空五笔词频 | 共享模型、待写状态、wubi_frequency 表；提升 epoch | 开关、所有短语、emoji、设置、剪贴板 |
| 清空自定义短语 | phrases；已删除且没有同码同文内置来源的关联学习 | 有效内置来源的学习、emoji、设置、剪贴板 |
| 删除单条短语 | 该短语及失效的关联学习 | 其他短语及其他有效学习 |
| 清空 emoji 使用次数 | emoji_usage 的次数和最近顺序 | 短语、词频、设置、剪贴板 |

清空大量短语时先批量核对来源，模型只扫描一次关联集合，不按短语逐次全表扫描。短语编辑与相关词频修改在同一数据库事务提交；仅准备相关来源的快照，不能顺便把其他尚未隐藏保存的学习全部落盘。没有联合清空按钮，不再在清空后全库 VACUUM。UI 只有后台成功后提示完成，失败提示重试。本地试打框明确区分“不保存整段试打正文”和“开启五笔词频时会学习候选使用习惯”，避免误导。
