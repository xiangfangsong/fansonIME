# 可选择内容的个人 JSON 备份

状态：已实现，电脑端验证及用户真机验收通过，用户已授权提交，未授权推送。日期：2026-11-13；基于 0.5.0 / `f3ab6c3`，目标 0.5.1 / 23。

## 问题与范围

用户要求仅通过 JSON 文件导入导出，双向选择自定义短语、emoji 使用次数、五笔词频、个性化设置。文件缺少的类别必须禁用。当前设置只有添加/删除短语和独立清空入口，没有批量备份。

## 当前实现

`LocalStore` 将四类数据和剪贴板放在独立个人库；`WubiFrequencyStore` 共享内存词频并在串行磁盘队列保存；服务每次开始/显示键盘读取设置，emoji 面板每次按次数和最近顺序重排。直接读写词频表会遗漏未保存学习，或被旧队列重新覆盖。

## 实现方案与取舍

- 使用平台 ACTION_CREATE_DOCUMENT / ACTION_OPEN_DOCUMENT，只经 content URI 访问单个文件，不请求持久 URI、目录、存储或网络权限。最低 API31；系统文件选择本身授予单文件访问权。
- 独立 `PersonalBackup` 格式/流式编解码、`BackupController` 设置页交互；不向服务按键回调增加业务。版本 1、标识 FansonIME，未导出类别完全省略；空类别仍保留，不能与缺失混淆。
- 短语合并去重；emoji 次数和最近顺序、五笔词频覆盖还原；设置只覆盖文件中有效白名单项。选择页明确提示覆盖语义，空记录允许还原为空；未选类别保持。剪贴板、输入正文、内置词库和临时开关不导出。
- 文件与解析在后台；磁盘写入沿用共享词频 I/O 队列。导出词频取同步内存快照，包含未隐藏保存的记录，不因导出触发日常保存。
- 所选类别在一个 SQLite 事务中应用，无 schema 变化。还原词频期间提升代数并暂拒学习反馈；事务成功后替换共享模型，失败保留原模型，恢复学习；不持模型锁做磁盘 I/O。排队的旧保存读新模型，不复活旧词频。引擎、宿主提交和原输入 worker 顺序保持。
- 解析限制总字节、条数、文本长度、数字范围、嵌套深度；拒绝重复字段、损坏类型及未来版本。先完整解析验证再选择/写库，失败无部分导入。无新增依赖、第三方内容、权限、日志或系统备份范围变化。
- 选择内容保留在进程内后台任务对象中以支持旋转，不把个人内容放入 Bundle；进程被回收则安全取消并提示重试。导入成功重建设置页，下次开始输入使用恢复的设置。

## 验证与验收

JVM 验证词频快照、恢复代数/失败保留；隔离 API31 AVD 验证四类 JSON 往返、缺失与空类别、单选隔离、短语去重、emoji 排序、设置白名单、错误回滚、词频未保存快照及旧保存不复活；设置页勾选禁用、系统选择器与取消。构建、资源校验、Lint、最终 APK 权限检查。只使用合成数据，不接触真机内容。

## 实施结果

按上述边界实现，无新依赖、权限或 schema。156 JVM、177 项完整隔离模拟器回归、17 项最终备份专项及零问题 Lint 通过；真实 SAF 保存/选回/确认导入通过，最终 APK 仅 VIBRATE。完整回归与最终归档的主 APK SHA-256 相同。2026-11-13 按用户指示完成真机覆盖安装，用户已确认验收通过并授权提交，未授权推送；命令、过程修正与限制见 [0.5.1 验证](../../validation/VALIDATION-0.5.1.md)，稳定契约见 [个人备份](../PERSONAL_BACKUP.md)。
