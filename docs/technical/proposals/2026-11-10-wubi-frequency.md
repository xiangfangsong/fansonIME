# 五笔本地衰减词频与隐藏时保存

状态：已实现，用户真机确认生效并授权提交，长期体验继续观察；2026-11-10；基于 0.3.3 / `f906f91`，目标 0.4.0 / 19。实施前用户要求开发后等待真机验收再提交；当前用户已确认功能生效并授权提交，未授权推送。

## 问题与范围

五笔当前按自定义短语、内置精确匹配、前缀补全的固定顺序查询。新增仅五笔的本地学习，默认开启；关闭恢复原查询及排序，停止学习但保留记录。英文、韩语、emoji 排序规则不变。密码、NO_PERSONALIZED_LEARNING 字段及内部 emoji 搜索使用固定五笔顺序，不学习。

## 当前实现与风险

- `WubiRepository.lookup()` 将当前码全部手动短语、至多 200 个内置精确项及补足至 40 项的前缀项合并，按文字去重。前缀 SQL 本身至多读取 80 行。
- `WubiEngine` 返回字符串提交列表，服务的 `enqueue()` 与 `enter()` 分别提交；第五码可能在同次操作提交旧候选并开始下一编码。仅根据最终 `code` 或提交字符串反推来源会漏计或误计。
- `LocalStore` version 1，无完整增量迁移；服务和设置各有实例，实例同步不保护跨实例业务。现有清空按钮同时删除短语和 emoji 次数。
- 不改变正文提交顺序、会话隔离和编辑器失败后的现有处理。学习只根据平台 `commitText()` 返回值判定，不能证明宿主实际落字，也不新增正文回滚。

## 算法与参数

记录键为 `(inputCode, sourceCode, sourceText, text)`：实际输入码、原始词条编码、转换前文字、最终候选文字。保存分数、更新时间及是否来自自定义短语；不保存逐次事件、上下文、输入框或应用身份。

```
effective = score * 2 ^ (-max(0, now - updatedAt) / 14天)
effective <= 0.25 时视为 0，恢复基础顺序
成功选择后 score = min(16, effective + 1)，updatedAt = now
```

时间单位为毫秒；按需计算，无闹钟、轮询、定时任务、周期后台工作。查询不改时间戳，查看/浏览不能延长记录寿命。再次使用先衰减再加分，不复活旧累积量。加载时校正未来时间戳，运行时负时间差按零处理，不额外加分；系统时间人为大幅调整仍可能改变遗忘速度。

14 天半衰期、16 分上限和 0.25 门槛是本版本经验参数，不宣称已通过用户研究。最多满分 84 天未用即失去加权。所有词同比衰减不会自行交换相对名次；失效门槛确保旧记录最终回归固定顺序。主动选择和自动上屏均加 1，本次不引入未经确认的差异权重或滞回规则。

排序在简繁转换后、读音装饰前执行：自定义精确短语、内置精确匹配、补全三个层级内按有效分数降序，同分保持原次序。候选来源随转换保留，简繁记录按最终文字分别学习。已显示的快照不因计分回调重排，下次查询才应用变化。

## 内存、容量与候选截断

纯 Kotlin 模型使用键哈希表查询分数；全局及每输入码的有序索引支持取常用记录、过期清理和淘汰。指数衰减的相对大小可用 `log2(score) + updatedAt / halfLife` 比较，避免有序索引随墙钟变化而每天重建。实际候选分数只计算一次后排序。

最多 20,000 条有效内存记录。达到上限继续学习时按最低衰减优先级逐条替换，保证输入期间内存不无限增长；隐藏时如触及过上限，批量整理至 18,000 条。过期记录优先移除，不删除词库和短语。待保存更新、删除集合也必须有界，不能让从未保存过的淘汰项积累无限 tombstone。

每次查询最多从当前输入码索引取 64 个仍有效的已学习来源，数据库按批核对原词条存在且编码匹配后补回；自定义短语本已完整查询。最终重新转换、去重、分层排序。历史分数不能凭空制造候选或复活已删除短语。这个补回上限是明确的性能边界：不是全量词典的无界排序。关闭学习严格走旧查询，不补回。

## 提交、线程和保存

- 引擎结果增加仅用于五笔的候选提交元数据（提交序号、输入码、候选），每个候选提交单独对应，不把附加标点/原始字母记为候选。
- 服务捕获会话、目标、学习资格和词频清除代数。主线程保持原批编辑与提交顺序，仅在对应提交返回成功、资格有效、代数一致时更新共享内存模型。失效发布完全不提交也不学习。
- 模型短临界区保护跨线程访问；五笔规则仍在原 worker，英文/韩语仍在主线程。存储组件进程内共享，不让设置和服务各维护一套学习快照。
- `onWindowHidden()` 触发后台保存；不以切面板/切输入框等同于隐藏，不增加定时/次数阈值写盘，也不在普通销毁时另加兜底保存。没有变化不写；保存请求合并，正常只提交变化行。
- 隐藏后在独立低优先级串行 I/O 队列整理并取不可变变化快照，SQLite 事务落盘。写入不占五笔 worker，也不持模型锁执行磁盘操作；版本号确认快照后清 dirty，写入期间新选词不能被误清。
- 进程被杀允许丢失未落盘词频。保存异常保留待保存变化，下一次隐藏再尝试，不定时重试，不影响五笔正常固定查询；不输出敏感异常详情。

## 数据、清空与迁移

`personal.db` 增量迁移到 version 2，事务建 `wubi_frequency` 表；保留所有设置、短语、emoji 次数和剪贴板历史。schema 初始化由进程内公共锁保护，各库连接仍使用 SQLite 事务。新增设置 `wubi_frequency=true`，旧库缺值默认开启。

三个按钮各有独立确认：清空自定义短语、清空 emoji 使用次数、清空五笔词频。前两者不清其他类数据，词频按钮不改变开关、短语或剪贴板。删除短语仅移除不再具有内置来源的相关学习；重复内置词条仍可用且保留对应学习。清空词频提升内存代数，拒绝清空前的迟到提交；所有词频保存和设置删除由同一 I/O 队列排序，避免旧快照在清空后复活。明确清空操作立即修改持久化数据，是“仅隐藏保存日常学习”的例外。

继续使用无备份私有目录、现有排除规则；不增加权限/网络/依赖，不记输入日志。该新增持久化仅限用户授权的候选计分。原创实现和文档继续 Apache-2.0，既有第三方授权保持，不复制 Rime 源码；指数公式仅作算法思想参考。
