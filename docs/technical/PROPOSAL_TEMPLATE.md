# 技术方案模板

适用于新增语言、跨模块功能、提交协议变更、数据库迁移及有明显兼容性影响的重构。小型修复直接更新技术文档即可，不强制写长方案。

复制下列结构到 `docs/technical/proposals/YYYY-MM-DD-主题.md`，并按新目录层级调整相对链接。未实现方案标明草案/待实现，不能把预期测试结果写成已通过；实现后将稳定规则归入 [技术文档](README.md)，方案保留取舍与验证证据。

# 方案名称

状态：草案 / 已确定待实现 / 实现中 / 已实现 / 已撤销

日期：YYYY-MM-DD；基于版本/提交：…；关联需求/问题：…

## 问题与范围

用具体触发场景描述现状、影响和期望结果，列明本次目标及必要边界。链接相关源码、产品要求与已有测试，不只写功能名称。

## 当前实现

记录涉及的类、方法、状态和依赖，说明当前代码为何产生上述行为。若修复 [待改进事项](KNOWN_GAPS.md)，填写对应编号。

## 实现方案与取舍

说明输入事件如何流经引擎、服务和编辑器；画图或列状态转换。记录关键选择、替代方案及未采用原因，只讨论影响实现和维护的差异。

| 关注点 | 本方案的具体处理 |
| --- | --- |
| 状态归属 | 新状态由谁持有、默认值、何时清空 |
| 线程与异步 | 执行位置、顺序、会话失效与过期结果处理 |
| 编辑器行为 | commits/composing、回车、退格、光标、切输入框和提交失败 |
| 面板与输入目标 | 宿主正文或内部搜索；切换前怎样 resolve |
| 数据与兼容 | 表结构/设置键、旧版本迁移、资源生成/哈希与回退 |
| 隐私 | 密码、隐私学习标志、剪贴板、日志、备份及权限影响 |
| 界面 | 高度/溢出/弹层、无障碍、横竖屏和语言兼容 |

## 改动清单

列出需修改/新增的文件与职责、依赖和资源变化；标明是否涉及第三方来源与许可。

## 验证与验收

给出正常路径、无匹配/失败/过期、快速输入、生命周期与已有语言回归的具体样例。区分 JVM、资源检查、仪器测试、真机及性能验证；用可观察结果说明何时算完成。

## 实施结果

实现后填写实际改动、命令和结果、未覆盖项、与方案差异、兼容/回退方式，并链接版本验证记录和已更新的技术章节。记录提交标识时使用真实值。
