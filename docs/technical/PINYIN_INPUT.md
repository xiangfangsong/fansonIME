# 离线全拼维护说明

0.5.0 / 22 新增。方案与取舍见 [实施方案](proposals/2026-11-12-pinyin.md)，实际结果见 [验证记录](../validation/VALIDATION-0.5.0.md)。

## 输入与状态

菜单顺序为 English、五笔86、全拼26键、한국어。正式全拼可设为默认语言，沿用已有偏好和地球短按回切；密码、数字、邮箱和网址字段仍按 EditorPolicy 临时使用英语，不覆盖偏好。

正式全拼和五笔临时拼音共用纯 Kotlin `PinyinEngine` 与只读 `PinyinRepository`。引擎只返回 `EngineResult`，经服务原输入链路编辑宿主；拼音和五笔都在同一 worker 串行，英文/韩语仍在主线程同步。拼音原始编码仅显示在内部候选栏，不写入宿主 composing。

- 无声调全拼支持单字、2–8 字词语；完整匹配优先，之后补充有限前缀结果。没有简拼、整句转换、纠错、网络、拼音学习或拼音自定义短语。
- `v` 表示 ü；兼容 `lve/nve` 与 `lue/nue`、j/q/x 后的 v。L 长按输入 `'`，明确音节边界，例如 `xi'an` 排除“先”。不输入分隔符也可查询“西安”。临时模式 L 仍保留五笔键帽，长按优先作为分隔符。
- 空格/普通语言或面板切换确认首项，不附加空格；无候选保留拼音，阻止这些切换和标点。候选选择确认整个字词，保留现有 text/code 重新核对；不做部分句子拼装。
- 有编码时回车上屏原始拼音，仅清码、不再换行/发送；无码回车按宿主动作执行。“五笔回车键功能”仅影响五笔。退格先删编码，无码才执行原字符簇删除。
- 简繁使用现有 OpenCC 转换；搜索固定简体。拼音不套用四码唯一、第五码顶字、五笔读音或词频规则。编码限 64 字符，拒绝开头或连续分隔符。

## 五笔临时拼音

服务把 `language`（菜单/键盘/偏好）和 `activeLanguage`（实际引擎）分开，`temporaryPinyin` 仅存于会话内存。

五笔长按 Z 进入并 toast“临时进入拼音输入”；再次长按退出。保留五笔键帽、字根、键高和空格标签，Z 为浅绿选中底色、深色图标，深浅主题均有独立状态说明。普通五笔 Z 短按查读音保持；临时短按输入 `z`，正式全拼使用普通 Z。

两向切换直接丢弃未上屏编码和候选，不确认首选。切换立即改变随后按键的路由，在同一 worker 中排入 reset 屏障，再发布清码；屏障前已排队的正文提交必须先执行，不能通过递增 session 或只保留最新结果丢弃它们。屏障后按键查询新引擎。真正的语言/输入框/隐藏会话仍沿用原 session 隔离并清临时标志。连续切换取消上一条模式 toast，会话结束也取消，避免过期提示排队。

选字后继续临时拼音；数字、符号、表情面板保留本会话模式。主动换语言、输入框、收起键盘后恢复普通五笔。地球长按仍用于菜单。

中文 emoji 搜索按实际引擎选词写入 `emojiQuery`，不向正文写中文。Z 切换只清当前编码，不清已确认关键词；选 emoji 后同时清两种中文引擎的未确认输入。

## 数据、索引和重建

主库为万象数据固定提交 `78aff0746503c0b9ab7f0a60e1cc8a7e38247c9c` 的两个词典文件，CC BY 4.0；未引入其程序或模型，也没有依赖 librime。清华 THUOCL IT 按 MIT 补词，仅使用已有整词读音校注，保守权重 1。原始资料、许可、修改说明见 [第三方声明](../THIRD_PARTY_NOTICES.md) 与 `third_party/pinyin/NOTICE.txt`。THUOCL 数据较旧，不能声称是最新词库。

执行 `python tools/prepare_pinyin_data.py`：校验锁定源文件，gzip 源解压后再次核对原始哈希；去声调并规范 ü 拼写，按编码/文字/音节去重，重复取最大频重；保留全部有效单字与按原频重取前 250,000 条的词组，再补 38 条 IT 词。当前 299,392 条规范记录，另有按音节生成的 24,814 条兼容拼写索引，共 324,206 条，覆盖 43,328 个不同单字、250,038 个不同词组。`coverage.json` 和 `data_info.json` 是实际审计结果，不等于覆盖保证。

`pinyin.db` 含 entries(code,text,syllables,weight,source) 和 completions(prefix,code,text,syllables,weight)，均有稳定排序索引。完整编码查全部精确记录并按文字去重，显式分隔符必须匹配原始音节边界。不足 64 项时追加前缀候选：1–3 字母预生成每前缀前 64 条，长前缀用索引区间限 64 条。精确项不截断，避免生僻字完全无法选择；候选展开使用同一快照，不继续分页。

兼容拼写只在生成阶段按音节展开：`nue/lue` 可用 `nve/lve`，j/q/x 后的 u 可用 v；不能对整串拼音直接替换 `nve`，否则“女儿”的 `nv+er` 会被误改成 `nuer`。前缀索引按词去重后选前 64 项。没有分隔符的普通查询不逐候选计算音节边界，明确输入 `'` 时才检查。

只读库 49,008,640 字节；首次复制到 noBackup 哈希命名文件并流式验证 SHA-256，避免整库读进堆，不修改个人库 schema，不添加权限/运行时依赖，不改五笔词库。更换源文件需要重新审核许可、固定版本和哈希、重建并验证 APK 内署名和许可。

## 限制

词组不是上游全部 150 万余条，专业词、人名、低频词和个别读音仍可能缺失；已知现代词覆盖不代表完整新词能力。短前缀仅有限补全，没有简拼、多音动态消歧或句子语言模型。固定频重不学习个人拼音习惯。大量同音字仍会增加既有候选 View 的创建和测量成本，资源/宿主失败回滚沿用 [已知缺口](KNOWN_GAPS.md)；真机及不同宿主体验需单独验收。
