## 0.4.2 英语句首自动大写与缩写候选

- 设置“英语句首自动大写”默认开启，与键盘“自动拼写”独立；普通文本句首只大写首字母，密码、邮箱、网址、数字不自动大写。依赖平台/宿主的句首判断，不做完整语法推断。
- Shift 使用空心箭头（小写）、实心无底线（自动首字母大写）、实心有底线（手动持续大写）。AUTO 点击取消当前词的大写，退格删空不立刻重启，下次新句恢复；再次点击可开启持续大写。手动持续大写、五笔 Shift 进入英语大写及韩语上档保持。
- 32 项常用缩写完整命中时优先，如 im→I'm、id→I'd、its→it's、youre→you're；原始输入第二，普通补全随后，去重且最多 80。短前缀不注入缩写。大小写跟随实际输入，I 的规范形式保留大写。
- 候选点击才替换当前预编辑；空格/标点/回车仍提交原词，its 不自动纠正为 it's。关闭自动拼写时不显示缩写候选，但仍可句首大写。英语 L 键长按 ASCII 撇号并显示小提示，支持词内继续预编辑/退格，L 主字母保留原居中单行，撇号在右上角。
- 真实移动光标、选区替换、语言/会话和重新打开时重新判断，拒绝自身旧回调打断新词；不读取全文或保存英文输入。完整状态、表格与边界见 [维护说明](technical/ENGLISH_INPUT.md)。

- 自行实现现代韩文确定性组字，覆盖 Unicode 的 19 初声、21 中声、28 种终声状态，共 11,172 个现代音节；处理复合元音、复合收音及后续元音导致的收音迁移。例如 ㄱ→가→간→가나，닭 后输入 ㅏ 变为 달가。独立字母仍可直接输入，双辅音由 Shift 输入，连续普通辅音遵循 PC 两式分界。
- 韩语直接使用宿主预编辑文字，不显示空候选栏或候选占位，地球和功能按钮持续可用。只保留当前音节与该音节实际按键的回退状态；正在组合时逐键退格，结束组合后的正文按完整字符删除。音节边界的前缀提交和下一音节预编辑在同一批编辑中完成，避免中间光标回调打断连续组字。
- 韩语空格、数字、标点、面板及语言切换先确认当前组合；移动光标、选择文字、结束输入会话时终止原组合，后续输入不能覆盖旧位置。回车一次完成组字并执行换行或编辑器发送/搜索等动作，不吞掉第一下回车；不套用五笔编码规则。
- 设置“回车键功能”改名“五笔回车键功能”，三选项及已存设置保持。字根、四码唯一、第五码与查读音只用于五笔；自动拼写仅用于英文。五笔 Shift 仍进入英文大写，英文大小写切换保持；韩语 Shift 独立处理上档字母。

## 0.2.0 Z 键与离线候选读音

- 五笔 Z 键改为“侧脸读出 Z＋放大镜”的本地矢量图标，保留清晰的 Z 字母，表示输入与查读音两种用途；读音显示时使用选中颜色和无障碍状态。英文模式仍是普通 Z/z，不受此功能影响。
- 无待处理编码时按 Z，将小写 z 放入预编辑编码，不立即上屏。回车遵循既有设置：上屏五笔编码时提交 z，清除编码时删除 z，上屏首个候选时因无候选保留编码供修正。z 不传给只接受 a～y 的五笔 SQL 查询。
- 有候选时按 Z，切换“五笔提示 / 读音提示”；编码和候选顺序保持，不提交文字。有编码而无候选时提示“暂无候选可查读音”，保留编码，不插入 z。
- 所有候选都补上读音，包括原来没有五笔码提示的精确候选。单字去重显示资料已收录的全部带调读音；词组优先查整词，可保留多个整词读法。没有整词记录的自定义词组标明“逐字”，逐个 Unicode 码点显示读音，不穷举多音字组合；未收录字符显示“暂无读音”。
- 顶部仍为原有 44dp 候选行，每个候选内部汉字在上、12sp 淡色拼音在下，不增加键盘高度。普通模式保留原有测量与无横滑规则；读音模式允许候选横向滑动，完整保留多音读法，不以省略号截断。溢出时仍使用原展开箭头，已有网格同步显示读音；读音网格使用两列留出空间，较长条目可在格内横滑，普通网格保留三列。不新增页面、长按、弹窗或设置开关。
- 读音状态归属当前五笔编码，继续补码、无匹配修正和退格时保持；退格清空、选词、提交、清码和结束输入会话后恢复默认。查读音期间暂缓四码唯一及第五码自动上屏，等待主动选字；结束后原设置继续生效。候选选择只提交原字词，提示拼音不进入宿主正文。
- 内置固定版本的 pinyin-data 与 phrase-pinyin-data，仅使用其数据，转换成只读 SQLite，后台串行查询、内存限量缓存；不引入在线接口或语音模型，不保存查询历史。使用已内置 OpenCC 映射补充繁体词组查询键，让“銀行、重慶”等保持词组消歧。
- 数据含 44,440 个单字、47,152 个原始词组及 33,219 个繁体查询别名。对当前 70,391 个五笔单字核查，41,467 字有读音，28,924 字未收录；缺失主要为扩展 B 区的 28,087 字。资料覆盖与五笔字库覆盖分别记录，不推断缺失读音，不改变原码表及排序。
- 原始数据、revision、SHA-256、许可和离线转换脚本随项目保留，应用“第三方数据与许可”可查看署名及 MIT 许可。版本和关于页面统一为 0.2.0，验证记录单独归档；真机覆盖安装前告知，用户验收后再按指示提交。

## 0.1.4 Emoji 与符号修订

### Emoji

- 移除“收藏”分类、收藏数据及相关操作，不再提供 emoji 长按弹层或长按后的动态重绘，避免该操作引发频闪。

- 取消长按肤色菜单后，将肤色等变体直接放入人物分类及中文关键词搜索结果，仍一次提交完整序列。

| 主工具栏 | 依次为模式、剪贴板图标、符号图标、emoji 图标、设置图标、向下小三角；向下三角位于设置右侧，点击收起键盘 |
| 底部工具行 | 删除“切换输入法”和“收起”整行；保留应用首页的系统选择入口，用户也可通过系统切换入口选择其他输入法 |
| 图标实现 | 使用本地矢量图形，避免随字体变化成方框；剪贴板、符号、emoji、设置、收起、Shift、换行均保留中文无障碍标签。剪贴板面板内的管理说明及操作文字仍保留 |

本轮不调整码表、候选排序、四码自动上屏、剪贴板历史或 emoji 数据。自动四码上屏已经发生时，回车不会撤回已提交的字词。

验收包括：有候选时回车提交原码、空格仍选首选、Shift 大写/小写循环与五笔86返回、工具栏图标及排列、底部工具行移除、系统注册名称与子类型数量，以及原有功能回归。先在本项目原模拟器测试；准备更新真机前先告知用户。

回归补充：系统切换输入法时可能销毁并重新绑定服务。销毁流程应先使旧会话和界面失效，再完成系统结束输入回调，最后关闭后台执行器与数据库；销毁中的回调不得再向已关闭执行器提交任务。此项作为系统切换流程的稳定性修复一并验证。

## 1. 产品目标与默认取舍

做一款安装到自己手机、可在各应用中使用的 Android 系统输入法：86 版五笔为主，英文、数字、标点和 Unicode emoji 为辅，安装后所有输入功能都能离线工作。

- 原生 Kotlin 开发；先做好软键盘，后续再完善外接键盘。
- 最低支持 Android 12（API 31），即 `minSdk = 31`。编译和目标 SDK 在实施时按本机开发环境与官方要求确定，不与最低版本混为一谈。
- 默认简体、半角字母数字、中文标点、固定候选顺序。
- 默认不保存输入历史、不自动学习字词频率；按用户要求仅保存 emoji 使用次数和最近顺序用于常用排序，允许手动添加常用短语，不提供 emoji 收藏。
- 提供浅色、深色和跟随系统主题，优先保证按键准确、响应稳定。
- 首版范围：五笔86、英文、数字、符号、emoji、剪贴板查看与粘贴、一键清空剪贴板、基本设置、启用引导。
- 后续范围：拼音反查、自动调频、本地图片表情包、词库导入导出、单手模式。

开发电脑下载 SDK、依赖与词库属于构建过程；手机端安装包内置运行所需资源，首次启动也不下载数据。

## 2. 键盘界面

从上到下分为工具栏、编码与候选区、按键区。宽度随屏幕适配，横屏使用较低键盘；键高、底部留白可调。

```text
┌───────────────────────────────────┐
│ 五笔86     📋    #+    ☺    ⚙    ▾  │
│ 编码：……                          │
│ 候选1   候选2   候选3   候选4   ▾  │
├───────────────────────────────────┤
│ Q  W  E  R  T  Y  U  I  O  P       │
│  A  S  D  F  G  H  J  K  L         │
│ ⇧  Z  X  C  V  B  N  M       ⌫     │
│123   简    ，    空格    。    ↵    │
└───────────────────────────────────┘
```

- 候选固定单行、不可横向滚动；中文和英文的可见候选均直接点击上屏。只有实际放不下时出现向下箭头，点击箭头在网格页选字；一行全部放下时不显示展开按钮。
- 顶部数字行默认开启，可在设置关闭；字根提示默认隐藏，开启后五笔字母键长按显示完整字根卡片，不再长按输入数字。
- 长按空格进入光标移动；只按操作需要读取有限上下文。
- 回车在无编码时显示换行图标或对应的搜索、发送等编辑动作；存在五笔编码时只提交原始字母，防止误选字和误发送。
- 按键支持按下反馈、可选震动；默认不弹出显示敏感字符的放大预览。
- 主工具栏使用本地矢量功能图标，设置右侧以向下三角收起键盘；键盘不再单设“切换输入法”按钮。应用首页保留系统输入法选择入口，适配导航栏、安全区域、横竖屏和字体缩放。
- 显示状态使用“五笔86 / 英文 / 隐私模式”等简短文本，设置页展示离线与数据保存情况。

设置页分为输入习惯、键盘外观、emoji、隐私与数据、关于。首次打开引导用户进入系统页面启用并选择输入法，附带本地试打区。

### 剪贴板面板（首版）

工具栏常驻“剪贴板”入口。点击后将按键区切换为剪贴板面板，保留返回键盘按钮。

```text
┌───────────────────────────────────┐
│ ‹ 返回键盘    剪贴板    一键清空    │
├───────────────────────────────────┤
│ 当前内容                          │
│ 复制的文本……                      │
│ 可滚动查看，长文本可展开           │
│                                   │
│             [ 粘贴 ]              │
└───────────────────────────────────┘
```

- **查看**：打开面板时读取系统当前剪贴板并显示文本；面板可见期间监听变化并刷新。剪贴板为空时显示空状态，无权访问时明确提示，不能将访问失败当成“已清空”。
- **粘贴**：用户点击后，将显示的文本提交到当前输入框，不自动发送消息。五笔编码尚未结束时沿用 emoji 面板规则：先提交有效候选，无匹配则保留编码并提示修正。
- **一键清空**：调用 `ClipboardManager.clearPrimaryClip()` 并清除本输入法的全部剪贴板历史和临时预览；不增加二次确认，系统清除失败时明确区分本地历史清除结果。
- **读取时机**：默认输入法服务运行时监听剪贴板变化，包括键盘或面板隐藏时；销毁服务时注销，不做轮询。系统限制或服务不在运行时可能无法捕获记录，不能恢复此前的复制历史。
- **数据保存**：按用户要求，在无备份私有目录保存最近 10 项普通文本，重复复制置顶，超出上限淘汰最旧项，关闭键盘及重启保留；支持历史粘贴、单项删除及一键清空。锁屏、隐私输入会话和标记为敏感的内容不自动记录。所有内容不写日志、不上传。
- **敏感内容**：剪贴板标记为敏感，或当前为密码输入框时，默认遮住内容，允许用户主动点击“显示内容”或“粘贴”；不自动预览，也不禁止用户主动粘贴密码。
- **内容类型**：首版完整支持文本。图片、文件等仅提示类型，仍可一键清空；不自动读取 URI 指向的文件，不将 URI 路径当作正文粘贴。图片粘贴后续按目标应用富内容能力适配。
- **更新与一致性**：粘贴前检查当前剪贴板是否与面板内容一致；若已被替换则先刷新并提示用户重新选择，避免粘贴意外内容。大文本限制首屏预览量，按需展开，不在 UI 线程进行昂贵处理。

技术上使用系统 `ClipboardManager`，作为当前默认输入法按系统规则访问，不需要网络或无障碍权限。系统可能限制访问或主动清空内容，面板应同步反映实际状态。

“一键清空”清除当前 Android 用户/资料空间中的系统当前剪贴板、本输入法历史及临时预览，不代表清除其他输入法、应用或厂商服务自行保存的历史副本。

来源：[ClipboardManager 读取与清除接口](https://developer.android.com/reference/android/content/ClipboardManager)、[敏感剪贴板处理](https://developer.android.com/privacy-and-security/risks/secure-clipboard-handling)。

## 3. 五笔输入规则

| 操作或状态 | 默认行为 |
| --- | --- |
| 字母编码 | 按五笔86码表匹配，标准编码最长四码 |
| 一、二、三级简码 | 展示对应简码字词，空格或点击上屏 |
| 候选排序 | 自定义短语、内置精确、补全分层；默认层内按本地衰减词频排序，同分保持码表顺序；关闭学习恢复固定顺序 |
| 空格 | 有候选时提交高亮候选；无编码时输入空格 |
| 四码唯一 | 有且仅有一个精确候选时自动上屏；可在设置中关闭 |
| 四码重码 | 保留候选等待选择；继续输入第五个有效编码键时，提交当前首选，再用该键开始下一段编码；此行为可关闭 |
| 无匹配编码 | 保留编码并提示，不自动丢码、不擅自提交字母；继续编码受四码上限约束 |
| 无候选时空格 | 保持原编码，允许退格修正；回车可明确提交原始字母 |
| 退格 | 优先删除一个编码字母；编码为空时删除输入框中的内容 |
| 编码中按标点 | 有候选时先提交高亮候选，再提交标点；无候选时保持编码并提示修正 |
| 编码中按回车 | 无论是否有候选，均只提交原始字母；下一次无编码回车才执行编辑器动作 |
| Shift | 五笔86 时提交未完成的原始编码并转英文大写；英文时在大写与小写之间切换，回五笔86使用模式切换按钮 |
| 切换应用或输入框 | 清空临时编码、候选和搜索状态，避免串入另一输入框 |

首版不默认启用联想、整句预测或拼音混输，避免改变五笔候选顺序。Z 键首版保留；后续可配置为离线拼音反查或通配查询，二者互斥。

常用短语通过设置页手动添加“编码 → 文本”。多字词生成编码时采用五笔86规则：两字取各前两码，三字取前两字首码及第三字前两码，四字及以上取前三字和末字首码。生成依据必须使用字的完整取码信息，不能直接拿一级简码拼接。

### 码表与词库

- 候选来源考虑 Rime 的 `wubi86.dict.yaml`，其仓库明确标注五笔86，码表可转换后独立使用；首版不需要嵌入完整 Rime 引擎。
- 已核对上游说明并集成固定 revision 的码表，保留原始文件、作者、许可和转换记录，详情见 THIRD_PARTY_NOTICES.md 与 resources.lock.json。
- 固定数据版本与 SHA-256，构建阶段转换、检查编码、去除重复项并生成索引；手机端不解析大份 YAML。
- 一级简码与首选顺序单独建立回归样本，防止不同码表的习惯差异。
- 内置码表 weight 使用 64 位整数；0.4.0 个人学习使用 REAL 衰减分数及 INTEGER 毫秒时间，不能与内置权重混淆。候选同时保留编码、文本、基础顺序和来源信息。

来源：[Rime 五笔仓库](https://github.com/rime/rime-wubi)、[码表](https://raw.githubusercontent.com/rime/rime-wubi/master/wubi86.dict.yaml)。

## 4. Emoji 与图片表情包

### 首版：Unicode emoji

- 内置 emoji 序列及中文名称、关键词数据，分类包括笑脸、人物、动物、食物、活动、物品、符号和旗帜。
- 不提供收藏或长按弹层；常用按本地使用频率排序且最多一页 30 项，其他类别与搜索保留分页。
- 肤色等变体在人物类别及搜索结果中直接选择，完整 Unicode 序列一次提交。
- 分类栏可横向滑动但不显示滚动条；同一 emoji 面板内切换分类或翻页重绘时保留原有水平位置。
- 面板内搜索框使用自己的临时输入状态，可用五笔输入中文关键词，搜索内容不会写进宿主应用。
- 主键盘编码未结束时点击 emoji：有候选则先提交高亮候选，再打开面板；无候选则保留编码并提示先修正或取消。
- 删除按可见字符簇处理，覆盖肤色修饰、旗帜、变体选择符和 ZWJ 序列；不能按一个 UTF-16 字符直接截断。对复杂序列结合内置数据和实际系统行为验证。
- 首版优先显示手机系统能渲染的 emoji，针对不支持的序列做隐藏或降级；发送后的外观取决于接收应用和对方设备。若后续需要统一面板外观，可内置字体，禁止依赖联网字体下载。

数据采用 Unicode emoji 序列与 CLDR 中文名称/关键词，固定版本并保留许可。数据存在不等于设备字体一定支持。

来源：[Unicode emoji 数据说明](https://www.unicode.org/emoji/charts/)、[CLDR 名称与关键词](https://cldr.unicode.org/translation/characters/short-names-and-keywords)。

### 后续：本地图片、GIF 表情包

通过系统文件选择器导入用户选择的图片，复制到应用私有目录，生成本地缩略图，不请求整个相册或全部文件权限。

根据目标输入框声明的 MIME 类型判断能否插入，通过 Commit Content API 和带临时读取授权的 content URI 提交。目标应用不支持时显示“当前应用不支持直接插入此类图片”，可由用户主动选择系统分享；不能承诺微信、QQ 等应用的所有输入场景都支持。

来源：[Android 图片键盘支持](https://developer.android.com/develop/ui/views/touch-and-input/image-keyboard)。

## 5. 隐私设计

| 范围 | 设计要求 |
| --- | --- |
| 网络 | 合并后的 Manifest 不含 `INTERNET`；无广告、统计、远程崩溃上报、在线字体或云词库依赖 |
| 权限 | 不索取通讯录、定位、麦克风、短信、无障碍或全盘存储权限；按需添加触感等与功能直接相关的普通权限 |
| 输入日志 | 调试版和发布版均禁止记录编码、候选、正文、密码和剪贴板内容 |
| 临时输入 | 仅保存在内存，输入会话结束、切换输入框时清空 |
| 本地数据 | 保存设置、手动短语、五笔衰减词频、emoji 次数/最近顺序和最近 10 项剪贴板普通文本；使用无备份应用私有存储 |
| 自动学习 | 0.4.0 仅五笔默认开启，可关闭；只记录必要候选身份、衰减分数和更新时间，不保存逐次或整段输入历史 |
| 密码与隐私字段 | 识别文本、数字等密码变体；禁用学习、联想、历史、emoji 推荐和字符预览；遵循 `IME_FLAG_NO_PERSONALIZED_LEARNING` |
| 剪贴板 | 默认输入法服务监听复制变化，保存最近 10 项普通文本；敏感标记、锁屏及隐私输入不记录；支持单项删除，清空同时作用于当前内容和全部本地历史 |
| 系统备份 | 禁用应用自动备份，并配置对应 Android 版本的云备份、设备迁移排除规则，不能仅依赖 `allowBackup=false` |
| 对外组件 | IME 服务由 `BIND_INPUT_METHOD` 权限保护，其余组件按最小暴露原则配置；图片提供器仅授予所选文件的临时读权限 |
| 清除与导出 | 短语、emoji 次数和五笔词频分别清空；剪贴板历史单独清空；导出仅由用户主动操作，并说明导出文件会包含哪些本地数据 |

“本输入法离线”指输入法自身不向服务器传输内容；提交给聊天、浏览器等目标应用后的数据由目标应用处理。这一边界在隐私说明中明确写出。

来源：[Android 权限参考](https://developer.android.com/reference/android/Manifest.permission#INTERNET)、[编辑器隐私标记](https://developer.android.com/reference/android/view/inputmethod/EditorInfo#IME_FLAG_NO_PERSONALIZED_LEARNING)、[系统备份与迁移规则](https://developer.android.com/identity/data/autobackup)。

## 6. 技术结构

本节于 2026-11-09 按源码核对，详细记录统一维护在 [技术实现文档](technical/README.md)，避免产品稿与技术稿重复描述后产生偏差。

- 单个 `:app` 模块，按 `ime/engine/keyboard/data/emoji/clipboard/settings` 包分责；隐私策略分布在字段判断、服务、控制器、存储及配置中，当前没有独立 `privacy` 包。
- 通过 `InputMethodService` 与 `InputConnection` 接入 Android；纯 Kotlin 的五笔、英文、韩语引擎返回提交与预编辑结果，由服务执行编辑。
- 五笔和读音 SQLite 查询使用后台单线程；英文与韩语的状态和 composing 更新在主线程同步执行。会话令牌和串行队列拒绝跨会话结果，当前没有独立查询序号。
- 使用原生 View、GridLayout 与 ScrollView；候选展开使用已有查询快照，并非数据库分页或可回收候选列表。
- 码表、读音库等由离线工具预生成，作为 assets 分发；运行时复制字典到无备份私有目录并只读打开。用户设置、手动短语、emoji 次数和剪贴板历史保存在独立 `personal.db`。
- 剪贴板监听绑定默认 IME 服务生命周期，面板隐藏时仍可按隐私规则记录；内部 emoji 搜索与宿主正文使用不同提交目标。

实现限制及后续优化方向见 [待改进事项](technical/KNOWN_GAPS.md)。
